# Уведомления по основанию задачи — локальный черновик

18 октября 2026. Код и тесты написаны локально; проверки не запускались,
миграция не применена, публикации нет.

## Поведение

- В общей панели уведомлений добавлен раздел «Согласование задач».
- Выбранный участник видит задачу, решение, название и точную версию документа,
  необходимость личного согласия либо свой текущий ответ. Отозванное согласие
  не считается молчанием и не подписывается «ждём ответа».
- Раздел «Что изменилось» сравнивает текущее основание с непосредственно
  предыдущим: решение, документ/версия, состав обязательных согласующих.
  Это НЕ сравнение с последней прочитанной или последней подтверждённой версией.
  Порядок людей и их ответы не считаются изменением состава.
- Текст документа и формулировка решения показаны в раскрываемых блоках «было» /
  «стало». Изменение типа или связей документа отмечается отдельно.
- Если сам документ обновлён, но основание ещё не пересохранено, отдельно
  сравниваются закреплённая и последняя редакции. Участника не просят подтвердить
  устаревшее основание: организатор сначала должен обновить его.
- Участник, исключённый из состава в последней версии основания, получает
  пояснение «согласие больше не требуется», пока остаётся участником проекта.
  Этот переход сравнивает только две последние версии, не все пропущенные.
- Организатор видит согласившихся, ожидаемых, отозвавших согласие и отдельно
  недоступных/вышедших участников. У ответивших отображается время последнего
  ответа на текущую версию. Выход из проекта не подменяется личным отзывом.
- Нажатие открывает карточку задачи, раскрывает её раздел и переводит фокус.
  В уведомлении нет кнопки, автоматически дающей согласие за человека.
- Для завершённых задач организатору видны ответы с пояснением, что изменение
  согласий не отменяет уже записанный результат. Новое согласие не запрашивается.

## Технические границы и приватность

`fk_task_basis_notifications()` — SECURITY INVOKER RPC, ограниченный
authenticated, с проверкой действующей сессии и текущего членства. Использует
RLS существующих таблиц. Имена читаются через существующую политику профилей;
при недоступном имени показывается нейтральная подпись. Никаких сервисных ключей.

Это производная панель актуального состояния, а не гарантированная доставка,
push/email, счётчик непрочитанного или полный журнал событий. Ответы после
подтверждения остаются видимыми; последний ответ заменяет предыдущий в рамках
версии. Текущий организатор видит все основания активных проектов, остальные —
свои текущие/непосредственно предыдущие назначения для незавершённых задач.
Закрытые проекты и чужие проекты не входят в выдачу.

Одна карточка на задачу, до 100 карточек с общим количеством и явным пояснением
ограничения, без пагинации. Сортировка по последнему изменению основания, ответа
или документа. Пропускные случаи и большие объёмы требуют проверки перед выпуском.
Снимок старше 60 секунд, офлайн или ошибка показываются как недоступные данные,
а не как «никого не ждём». Обновление выполняется существующей кнопкой загрузки,
без отдельного таймера. Нет новых таблиц, личных копий, маркеров прочтения,
телеметрии или изменений правил выгрузки/удаления.

Исправлены две связанные точки интерфейса: переход к задаче выполняется после
создания нового DOM и общий рендер больше не снимает disabled, выставленный
логикой согласований. Серверные проверки согласия остаются обязательными.
Тексты для 11 языков — черновые, не лингвистически принятые.

## Отложено до разрешения проверок

- Применение миграций, grants/RLS: посторонний, вышедший, текущий участник,
  организатор, заблокированный/недоступный профиль, закрытый проект.
- Два аккаунта: первое назначение → ответ → отзыв → новая версия → новые ответы.
- Изменение только состава, только решения, документа; новая редакция вне
  основания; удаление связанного документа/решения/аккаунта.
- Проверка сортировки, ограничения 100 и отсутствия дублей карточек.
- `tests/unit/task-basis-notices.test.mjs`, прежние тесты, сборка, мобильный
  браузер, RTL, доступность фокуса и переход на завершённую задачу.

Ни одна проверка в данном шаге не выполнена.
