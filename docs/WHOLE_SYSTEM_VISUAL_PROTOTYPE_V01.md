# Whole-System Visual Prototype v0.1

Date: 4 October 2026
Status: visual/information-architecture lab; NOT production truth.

## Purpose

The owner asked to see the full merged FOLKOOP as one application and to be free to radically restructure the interface if that makes the product easier to understand.

This lab therefore combines current FOLKOOP with the preserved intent of:
1. Sverinav;
2. FOLKUNO online + physical/hybrid;
3. Pavel's cooperative social-network concept;
4. attributed Tokarenko/KООПСЕТЬ research ideas;
5. ГБГ Форум;
6. Mura;
7. SDCF;
8. Web3/Web4;
9. blockchain;
plus the current codebase as the integration host.

These are not separate products in the participant UI.

## Proposed participant-facing structure

Primary surfaces:
- My FOLKOOP / Mura;
- Together;
- City;
- Center;
- Messages.

Projects, People, Communities and the economic/governance/trust tools become contextual workspaces rather than a growing permanent-tab list.

The first screen is intent-first:
- I need something;
- I can help / offer a resource;
- I want to do something together;
- I want to find opportunities nearby.

## Whole-system story

The reference story is Mura organising a repair / skill-sharing day:

local community -> optional Host -> sourced city/partner place -> people/skills/resources -> project -> shared purchase/economic flow -> fulfilment -> agreement/decision -> action -> outcome/evidence -> optional credential/integrity proof.

The lab explicitly labels capabilities:
- Live;
- Prototype;
- Planned.

A visual story does not upgrade a Planned item into a runtime capability.

## Design thesis

The interface should expose human jobs-to-be-done and relationships, not internal source projects or technology families.

SDCF, evidence, credentials, Web3/Web4 and blockchain appear contextually on decisions, roles, resources, outcomes and cross-organisation trust rather than as permanent tech tabs.

## Safety and truth boundaries

- no real external writes;
- no copied Telegram/forum messages;
- no fake partner status;
- no fake booking/payment/authority action;
- no fake blockchain receipt;
- no mandatory wallet/token/DAO;
- Mura remains authored illustrative data.

## Promotion rule

Nothing from this lab moves to production merely because it looks good. Promote a pattern only after:
1. owner review;
2. clear mapping to preserved requirements;
3. implementation/security/privacy review;
4. regression plan;
5. product evidence appropriate to the change.
