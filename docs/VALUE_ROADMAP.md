# Accepted value roadmap — 23 September 2026

Direction: save time on a familiar journey and identify relevant civic changes. Adoption is unproven; a simulated review is not a user study. This document records accepted priorities, not a promise of completed functions or dates.

| ID | Priority | Work | Status and acceptance condition |
| --- | --- | --- | --- |
| VAL-01 | P0 | Honest labels and geographic scope | Pending. Weather area must not imply whole-home filtering; an external journey link must not imply a personal trip; a city consultation deadline is not a personal obligation. Retain eleven languages and visible errors. |
| VAL-02 | P1 | Minimal voluntary setup | Pending. One stop/direction and one area or project. Skip/delete options, explicit local storage, no account/GPS required for onboarding. Storage denial must not break use. |
| VAL-03 | P1 | Departures as an answer | Pending authorised data access. Next 2–3 departures, real-time versus timetable distinction, cancellations and stale/error states. Keys never in the public client. A saved official departure board is only a handoff until an API is connected. |
| VAL-04 | P1 | Relevant changes | Pending. A verified reason for each selection; no inferred politics or guessed address relevance. Changed fetchedAt is not new content; disappearing records are not proof of resolution. First visit is an initial view, not dozens of new alerts. |
| VAL-05 | P2 | Saved dates and calendar actions | Pending. Verified deadlines, stable calendar IDs, correct Stockholm dates, original source. Calendar export is not push delivery. Never invent an individual waste schedule. |
| VAL-06 | P1 | Problem location, not only phone location | Pending. Select and confirm a road segment manually; GPS optional. No recipient guessing at ambiguous road matches. No simulated submission or status. |
| VAL-07 | P0/P2 | Compact useful hierarchy | Compact v0.12 exists. Future personalization pending. Keep four tabs, readable text, visible source/failure states and no filler documents or engagement tricks. |
| ABOUT-01 | Current | Author, history, FAQ and public contact | Implemented in v0.13 code; release acceptance depends on CI. Existing #om extended; no private biography/contact exported. |

Recommended order: VAL-01, then VAL-02/03 subject to API access; VAL-04 initially on explicitly followed projects if reliable geography is absent; VAL-05 small calendar step; VAL-06 before scaling fault reports.

Do not start a ticket-selling business, general authority-news feed, compulsory login, gamification or another large redesign as a shortcut to retention. Real tickets require an official agreement and valid ticketing integration.

## Pilot criteria — targets, not findings

Compare the same tasks in the user's familiar services and Sverinav, alternating test order. Recruit a small group of regular local public-transport users, then allow voluntary use without daily researcher prompts. Record task time, task success, source comprehension and specific useful discoveries. Minimize personal data. A good notification can save an app opening; raw daily opens are not the goal. Complete a real-device iPhone pass first.
