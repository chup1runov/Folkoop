## Architecture

The original Swedish, English and Russian shell copy remains in the existing modules.

The eight additional complete locales are stored in `folkoop-i18n-extra.js`. The shell, Home, network UI, onboarding/helper and OAuth callback consume that shared registry.

`FolkoopCopy.FULL` now contains all 11 supported languages. The previous normal English fallback for newer FOLKOOP sections is no longer part of the product contract.

The City/civic layer already had broad 11-language copy coverage. v0.30 additionally localizes remaining document/accessibility text such as the skip link, main-menu label, language-button label, page title and description.

## Regression protection

`tests/i18n.test.mjs` checks:

- exact translation-schema parity with the English baseline;
- no missing keys;
- no extra keys;
- no empty translation values;
- no excessive English fallback in the eight added locales;
- all renderers actually consume the full-language registry.

Browser coverage exercises all 11 languages, including RTL behavior and horizontal-overflow checks.

The normal project CI also covers deterministic tests, Chromium interactions, WebKit/Mura onboarding and geometry, source contracts, Auth readiness and network/database authorization.

## Important limitation

Automated tests establish completeness, wiring, rendering and regression safety. They do **not** establish native-speaker linguistic quality for every sentence.

Before treating a locale as editorially final, a native-speaker or professional localization review is still recommended, especially for:

- Somali;
- Persian;
- Kurmanji Kurdish;
- Bosnian/Croatian/Serbian wording choices;
- Arabic product terminology.

Any future UI string added to the English baseline should be added to every supported locale in the same change; the i18n tests are intended to fail otherwise.
