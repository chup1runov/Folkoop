# Общая потребность → отклики → проект

18 октября 2026. **Локальный непроверенный код, не опубликован.**
Продолжение кооперативного сценария, не новая параллельная сущность потребности.
Проверки и применение миграции отложены по просьбе владельца.

## Сценарий практики шведского

1. В разделе «Вместе» создать потребность по шаблону «Практика шведского».
   Создаётся обычный `fk_cooperations(kind='need')`, без вымышленных участников,
   ведущего, даты или подтверждённого помещения. Автор может отредактировать
   описание существующими средствами.
2. Другой человек открывает потребность и вступает в обсуждение штатной кнопкой.
   Это членство обсуждения, не подтверждение посещения мероприятия.
3. Каждый сам выбирает «Мне интересно», «Могу помочь» или обе отметки и пишет
   необязательные пожелания: уровень, время, формат, предлагаемую помощь.
4. Видны уникальные откликнувшиеся, отдельные количества интереса/помощи и
   пожелания. Количества не складываются: один человек может отметить оба пункта.
5. Автор создаёт связанный проект. Копируются только заголовок, описание и место.
   В новой команде автоматически только её создатель по существующим правилам.
   Отклики, чужие заметки, роли, задачи и согласия на встречу не переносятся.
6. Люди сами открывают проект и присоединяются к команде. Посещение встречи
   подтверждается отдельно в существующем блоке условий встречи.
7. В потребности есть ссылка на проект, в проекте — на исходную потребность.
   Создание проекта не помечает потребность выполненной.

## Права и жизненный цикл

- Отклики видны участникам обсуждения с активной пилотной сессией. Нет публичной
  выдачи пожеланий. Пояснение о видимости находится рядом с формой.
- Редактировать/отозвать можно только свой отклик. Пустые обе отметки удаляют
  отклик; отдельная кнопка отзыва делает то же. Удаление членства удаляет отклик.
- Отозвать можно и после закрытия потребности, добавить/изменить — только пока
  она открыта/активна. Максимум 200 откликов, пояснение до 500 символов.
- Проект создаёт только текущий автор потребности, пока она открыта/активна.
  Блокировка строки и уникальная связь исключают два проекта от повторного
  создания из одной потребности. После удаления проекта связь становится null
  и автор может создать новый. Сама потребность при этом не удаляется.
- Удаление потребности удаляет её отклики и связь, но не удаляет проект.
- Связь видна участникам любой из двух сторон; содержание другой стороны
  остаётся под существующими правами доступа, без автоматического членства.
- Членство и отклик не являются согласием на будущие изменения условий.
  Сохранённые пожелания не превращаются в обязательства после правки описания.

## Код и границы

Добавлены `fk_need_responses`, `fk_need_projects`, self-response RPC и RPC
создания проекта из потребности. Новые операции следуют существующим
session/member guards. UI — `network-needs.js`; 11 языков с черновыми переводами.
В иллюстративной встрече Муры есть пояснение исходной потребности, без реальных
записей или сетевых действий.

Свой отклик входит в bounded export (24 коллекции). Private inventory v6 включает
предыдущую v5 и число откликов. Нет импорта данных форума или внешних рассылок.

Не добавлены: поиск/слияние похожих потребностей, автоматические рекомендации,
резервирование ресурсов, автоматические приглашения, выбор нескольких проектов
для одной потребности, версионирование пожеланий. Шаблон использует обычное
создание потребности: после неопределённого сетевого сбоя перед повтором следует
обновить список, чтобы не создать дубликат. Идемпотентность гарантируется кодом
связи need→project, но не объявляется для старого createCooperation API.

## Отложенная приёмка — не выполнена

Два аккаунта: автор создаёт потребность → второй откликается/помогает → меняет
пожелания → автор создаёт проект → второй сам вступает → отдельно подтверждает
условия встречи. Проверить отзыв, двойную отправку создания проекта, счётчики,
закрытие/удаление, чужой ответ/чужое создание проекта, отзыв сессии, RLS, смену
аккаунта, XSS, локали/RTL, экспорт и inventory v6. Обновить export fixtures до 24.

Клиент не публиковать раньше миграции: экспорт и блок потребности требуют новых
таблиц. Сборка, тесты, SQL и браузер в этом шаге не запускались.
