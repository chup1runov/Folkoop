## Цель и выбор приоритета

Получить достоверную браузерную проверку на точной версии кода перед следующей
проверкой сценария кооперации. Установка браузера должна завершаться, а smoke
действительно выполняться. Зелёный результат не получать отключением WebKit.

По сохранённой выборке 28 октября job webkit упал на установке Playwright/WebKit;
сборка и браузерный smoke в этом job пропущены. validate успешен, deploy пропущен.
Это свидетельство сбоя проверочной инфраструктуры, не доказательство поломки сайта.
Свежий статус и корневая причина пока неизвестны. Если сбой уже исправлен, собрать
доказательство и не создавать лишний патч. Если он был временным, не менять
версии/runner без основания и не считать один повтор доказательством причины.

R01 / PR #281 (явные права новых таблиц) остаётся отдельным P0-пунктом перед
приёмкой новых SQL. Он не отменён и не закрывается этой задачей. Полный сценарий
«потребность → встреча → согласия → результат» требует обоих направлений проверок.

## Границы

Сейчас: только спецификация, состояние, локальные источники и самопроверка плана.
При реализации после следующего поручения: диагноз и минимальный локальный патч
CI/проверочной инфраструктуры с сохранением покрытия. Предпочтительный список:
.github/workflows/pages.yml, scripts/ci/webkit-smoke.sh; новые тесты конфигурации
только если защищают выявленную причину. Если проблема вне этих файлов, сначала
описать найденное основание и скорректировать план, не расширять его молча.

Не входят: продуктовый UI/логика, SQL/БД, аккаунты/письма, миграции, новые пакеты
без необходимости, платные сервисы, обновление всех Actions, merge/commit/push,
публикация и массовое переписывание накопленных изменений.

Важно: pages.yml запускает deploy для не-PR событий. **Не делать rerun или
workflow_dispatch существующего main workflow при запрете публикации**: исправный
повтор способен развернуть сайт. Удалённый запуск требует доказанно изолированного
validation-only маршрута и отдельного разрешённого внешнего действия. Отсутствие
такого маршрута оставляет удалённую проверку pending, не повод отключать gate.

Контрольные случаи до реализации: (a) ошибка установки остаётся failure;
(b) успешная установка с упавшим smoke тоже failure; (c) установка и все smoke
успешны на зафиксированной версии; (d) путь /Folkoop/ сохранён; (e) отсутствующий
лог/remote run даёт unknown/pending, а не invented pass; (f) запрет публикации
сохраняется даже при возможности rerun. Подробный regression выбирается по
реальной причине, которую ещё предстоит установить, а не выдумывается заранее.
