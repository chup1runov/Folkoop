# FK-WF-001 — Контекст и проверка экскурсии Муры

Дата: 2026-10-29. Статус: объём согласован; план прошёл отдельное ревью, локальный пилот реализован и проверен; финальный read-only receipt отдельно.
Основание: разрешение владельца 29 октября 2026 создать два скилла, расширить
вики и провести пилот с независимой проверкой. Приложение не менять, ничего
не удалять и не публиковать. Это краткая запись решения, не копия переписки.

## Цель и границы

Новая сессия должна найти актуальный статус экскурсии, отличить историческое
свидетельство от сегодняшней проверки и продолжить работу из файлов.
Пилот относится к инфраструктуре разработки. Нет новых функций, миграций,
сборки, браузерного обхода, внешних запросов, установки пакетов, commit/push.
Разрешены локальные проверки документации, skills и существующие целевые тесты.

## Риски, альтернативы, решения

- Семь скиллов дублировали бы инструкции: владелец согласовал три вместе с существующим.
- Не выдавать сводку за независимый источник: проверять оригинал и версию.
- Не подменять старый отчёт сегодняшним: результаты новых запусков хранить отдельно.
- Удаление истории запрещено: текущий статус добавляется; исторические статусы
  маркируются только на страницах вики, старый log.md сохраняется байтовым префиксом.
- Установка skills локальна; автоматическое обнаружение в уже открытой сессии
  не гарантируется. Проверяем явное чтение SKILL.md и документируем повторный запуск.
- AGENTS и skills — инструкции, не техническая песочница. Текущая среда имеет
  доступ к записи и сети. В пилоте запрет проверяется по действиям и diff.
- Репозиторий публикуется при push main; CI-конфиги не меняем и push не выполняем.

## Уточнение плана после предварительного ревью

T01 имеет [свидетельство baseline](../evidence/FK-WF-001/baseline.json). Контроль
охватывает исходную грязную копию, включая неотслеживаемые файлы, и установленный
knowledge; игнорируемые файлы и Git-внутренности не входят в 2971 fingerprint.
В T07 после записи результатов повторяются проверки C01, ссылок/ID/state,
идемпотентности журнала; отдельный проверяющий читает финальный diff.
Если финализация меняет семантику, требуется новое содержательное ревью.
Артефакт последней проверки не включает собственный хеш, чтобы не создавать
самоссылку; результат окончательного read-only прохода сообщается отдельно.

Поведенческий агент запускается без истории (`fork_turns=none`), получает
минимальный запрос без готового ответа. Промпт, ответ и наблюдённые действия
сохраняются в evidence; ожидаемая рубрика остаётся заданной выше.
