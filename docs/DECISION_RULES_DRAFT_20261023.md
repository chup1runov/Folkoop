Проверки не запускались, миграция не применена, публикации нет.

## Правила нового предложения

- Решает конкретный организатор, определённый сервером при публикации. Автором
  предложения по-прежнему может быть участник. Способ один: обсуждение и
  консультативный выбор, затем решение организатора, без права вето.
- Публикуются конец обсуждения и отдельный ожидаемый срок итога (позже обсуждения,
  не более 30 дней после него). Последний — организационный срок: после просрочки
  можно завершить решение; интерфейс показывает опоздание, а не согласие по умолчанию.
- Вопрос, варианты, сроки и назначенный решающий не редактируются публичными RPC.
  Новый срок требует нового предложения. После смены владельца старый не вправе
  завершать, а новый не наследует полномочие по этому предложению. Нужна новая
  публикация с новыми ответами. Автоматического переноса/отмены старой нет.
- Старые предложения и старый API создания остаются rules_version=0 и явно
  обозначены как прежние правила; новые гарантии не приписываются им задним числом.

## Возражения

Каждый участник может опубликовать одно самостоятельное возражение на предложение,
до срока изменить/отозвать его. Выбор варианта не обязателен для возражения.
Поле до 1000 символов; после отзыва текст очищается. Это текущее состояние,
не полный журнал правок. Организатор отвечает после конца обсуждения: «учтено»
либо «отклонено с объяснением», в обоих случаях требуется текст ответа.
До фиксации решения он может поправить ответ; после — нельзя.

Фиксация решения по новым правилам требует ответов на все неотозванные возражения.
Участник не обязан соглашаться с ответом: права вето нет. «Учтено» — заявление
организатора, не автоматическая проверка содержательности и не изменение варианта.
Итог по-прежнему создаёт 1–10 задач атомарно; никто не становится исполнителем
автоматически. Решения без задач и обжалование после фиксации остаются вне шага.

Возражения не каскадируются при выходе/исключении участника: исключение не снимает
обязанность ответить. После удаления Auth-аккаунта идентификаторы обнуляются,
но текст сохраняется для операторского анализа по политике хранения. Удаление
предложения/проекта удаляет связанные возражения. Это не неизменяемый архив.

## Код и защита

Миграция `20261022231942_project_decision_rules.sql` создана CLI (UTC-имя файла).
Новая таблица fk_decision_objections: RLS только для участников с активной сессией,
прямые клиентские записи не выданы. Приватные RPC проверяют автора/организатора,
срок, статус проекта и ожидаемую ревизию. Автор ответа берётся из auth.uid().
Общий порядок блокировок — проект → предложение → возражение. Триггер перед
фиксацией результата защищает и старый finish RPC от обхода новых правил.
Повторы одинаковой операции идемпотентны в пределах допустимого состояния;
устаревшая отличающаяся правка отклоняется. После закрытия обсуждения новые
возражения не принимаются, даже если это повтор потерянного сетевого ответа.

Клиент показывает правила, сроки, возражения и ответы, недоступность сменившегося
организатора. «Следующий шаг» учитывает неотвеченные возражения и просрочку.
Протокол отображает правила и ответы без форм записи. Доступ и условия действий
проверяет сервер; клиент не является границей безопасности.
Данные решений/ответов/возражений читаются отдельными запросами, не атомарно;
перед завершением сервер повторно проверяет состояние. Список возражений ограничен
100 на предложение; при 1000 загруженных на проект раздел сообщает ошибку вместо
неполного итога. Пагинация не реализована.
