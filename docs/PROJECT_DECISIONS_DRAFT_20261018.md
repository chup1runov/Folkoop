# Совместное решение → задачи: локальная реализация

Дата: 18 октября 2026. Статус: **код написан, проверки отложены по просьбе владельца**.
Ветка: `codex/project-decisions-draft-20261018`.
Не применять этот документ как свидетельство успешной проверки или публикации.
База Supabase и GitHub Pages в этом шаге не изменялись.

## Что добавлено

В карточке проекта — обсуждение с вопросом, целью, 2–6 альтернативами и сроком
ответа. Предложить его может текущий участник открытого/активного проекта.
Вопрос и варианты после публикации не редактируются: ответ не должен оказаться
под изменённым вопросом. Не более 50 предложений на проект, срок до 90 дней.

До срока каждый участник может выбрать вариант, дать пояснение, изменить или
отозвать свой ответ. Все ответы подписаны и видны текущим участникам проекта.
Это консультативное обсуждение, не обязательное голосование и не обещание
выполнить работу. Отсутствие ответа не означает согласие. Нет порога, при котором
система сама объявляет решение принятым. Даже при отсутствии ответов организатор
может записать собственное решение; интерфейс не называет его общим согласием.

После срока текущий организатор выбирает вариант, объясняет причину и задаёт
1–10 названий задач. Запись решения и создание обычных `fk_project_tasks`
выполняются одной транзакцией. При ошибке не должно оставаться части задач.
Задачи без исполнителей, связь `source_decision_id` ведёт к исходному решению.
Изначальный список задач сохраняется в решении даже после изменения/удаления
рабочих задач. Их текущий статус виден в блоке решения и штатном списке задач.
Обычные права управления задачами не переписаны.

Повторная отправка того же предложения использует UUID черновика; повторное
завершение с теми же параметрами не создаёт задач заново. Отличающаяся повторная
запись решения отклоняется. Произвольного параметра автора в RPC нет.
Проверки сессии, членства, роли и срока находятся на сервере, а не только в UI.

Для Муры добавлена короткая иллюстрация в проекте встречи на шведском.
Для 11 языков добавлен черновой текст; RTL предусмотрен для арабского/фарси.
Ни технической, ни человеческой языковой приёмки в этом шаге не было.

## Данные и доступ

- Новые таблицы: `fk_project_decisions`, `fk_project_decision_responses`.
- RLS: чтение только участникам проекта с действующей пилотной сессией.
- Изменения только через ограниченные RPC. Текст экранируется при выводе.
- Черновики форм хранятся в памяти и очищаются при смене авторизации.
- Выгрузка расширена с 20 до 22 коллекций: свои ответы, видимые собственные
  предложения и решения, зафиксированные пользователем. Это по-прежнему
  ограниченная выгрузка доступных записей, не полный архив аккаунта.
- Добавлена операторская inventory v4 поверх v3. Личные ответы удаляются
  каскадом членства; общие решения требуют проверки текста перед закрытием
  аккаунта. SET NULL сам по себе не удаляет личные сведения из свободного текста.
- Списки решений/ответов читаются отдельно: это не атомарный снимок голосования.
  Счётчики — текущие доступные ответы, а не неизменяемый юридический протокол.
  При достижении лимита ответа API блок показывает недоступность, не неполный итог.

## Осознанные ограничения первого варианта

- Нет изменения опубликованных вариантов, отмены предложения или обжалования
  результата. Коррекция пока требует нового предложения с объяснением связи.
- Нет автоматических уведомлений, кворума, делегирования, юридического голосования.
- Завершение требует хотя бы одну задачу. Решения без действий — следующий шаг.
- Выбор исполнителей сохраняет прежнюю механику проекта. Самостоятельное принятие
  задачи участником здесь ещё не реализовано.
- Время ввода — локальное время устройства; сервер хранит timestamptz.
- Просроченная страница может показать старую форму; сервер всё равно проверяет
  срок. Есть явное обновление. Отдельные сообщения для конфликтов пока не добавлены.
- Иллюстрация Муры — короткая реплика, не полный интерактивный сценарий решений.

## Отложенная приёмка — НЕ выполнена

1. Проверить синтаксис, сборку, RLS/grants и ошибки миграции на локальной базе.
2. Адаптировать export fixtures/ожидания с 20 на 22 коллекции и добавить тесты RPC.
   Allowlist новых приватных RPC уже внесён в security-definer contract, но не запускался.
3. Два новых тестовых аккаунта: предложение → ответы → изменение/отзыв до срока →
   завершение организатором после срока → задачи без исполнителей.
4. Отказать постороннему, бывшему участнику, отключённому пилоту, отозванной
   сессии, неорганизатору при завершении; запретить прямые INSERT/UPDATE/DELETE.
5. Пограничный срок, неверные варианты/индексы, пустая причина, слишком длинный
   текст, лимит задач, откат всей транзакции, XSS-текст, разные часовые пояса/DST.
6. Двойной клик/потеря ответа/два окна: без дубликатов; изменение завершённого
   решения отклоняется; удалённые рабочие задачи не появляются заново от retry.
7. Экспорт, закрытие только отдельного тестового аккаунта, сохранность чужих задач,
   прекращение доступа после выхода из проекта, ручная редактура персонального текста.
8. Проверить 11 языков, RTL, клавиатуру, мобильную ширину, Муру и смену аккаунтов.
9. Только отдельным следующим шагом: применить миграцию, опубликовать совместимый
   клиент и проверить живую версию. Клиент с новыми export-запросами нельзя
   выкатывать раньше миграции: старой базе неизвестны две новые таблицы.

Продолжение разработки без проверок возможно; это не означает готовности релиза.
