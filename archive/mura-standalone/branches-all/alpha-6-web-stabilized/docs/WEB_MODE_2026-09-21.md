## Goal

A user should be able to open a normal web URL and immediately get Ksyusha in a contained browser world, without installing Electron or bypassing Gatekeeper.

Web Mode is intentionally not a second independent product model. The browser model mirrors the desktop rules that make sense in a sandboxed tab, while OS-only desktop capabilities remain Desktop Mode.

## Implemented

- Ksyusha assets embedded in the browser bundle;
- cursor attention and radial actions;
- first-run onboarding;
- consent-first file metadata handoff;
- onboarding pause/resume when a handoff opens;
- explicit Remember;
- browser-local Focus timer;
- Quiet mode;
- first-seven-active-day continuity;
- relationship derivation;
- windowsill-plant episode progression;
- Home scenes and symbolic room props;
- browser-local persistence and reset;
- accelerated active-day controls for product testing;
- static-server mode and Vercel static-host configuration;
- Playwright Chromium acceptance specification.

Dropped file contents are not read or uploaded. Web Mode stores only the metadata needed for the explicit handoff simulation in browser-local state.

## Hosting

No backend is required for this Alpha 6 Web Mode.

Deploy root directory:

```text
web-preview
```

Entry:

```text
index.html
```

Static files:

```text
index.html
style.css
assets.js
model.js
app.js
vercel.json
```

`server.cjs` is optional for local HTTP testing and is not required by a static host.

The next operational step is to connect a static-host provider and deploy `web-preview/` to a public HTTPS URL.

## Browser boundary

Web Mode cannot provide:

- true transparent always-on-top placement above other applications;
- click-through over Finder/Chrome;
- system global shortcuts;
- native Accessibility/window geometry;
- sitting on or following actual application windows;
- Finder/Explorer reveal/open;
- menu-bar/tray integration.

Those remain Desktop Mode.
